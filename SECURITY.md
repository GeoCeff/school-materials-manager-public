# Archive Search security and vulnerability reporting

Prepared October 16, 2026. Archive Search is a personal, experimental project shared as [MIT-licensed source](LICENSE). This repository publishes no prebuilt Windows binary or shared provider configuration. Report security issues privately to **geogabaisen@gmail.com**. Include the version, Windows version, affected behavior, impact and a minimal synthetic reproduction. Do not include tokens, passwords, real coursework, student records or your full local profile. There is no automatic report upload, bug-bounty promise or guaranteed response time. We aim to acknowledge, reproduce, prioritize and privately coordinate a fix, then document affected versions and residual risk before a wider release. If email is unsuitable for sensitive details, first request an appropriate private exchange method without attaching secrets.

## Protection boundaries

- The renderer is sandboxed with context isolation and no Node integration. IPC checks the exact app window, main frame and URL. Network/navigation/new windows/webviews and Chromium device/location/notification permission requests are denied. Native sign-in runs in the system browser through trusted main-process code.
- Provider access is optional, read-only and reviewed. Fixed credentialed endpoints refuse redirects. Google uses loopback OAuth, state, PKCE and one-use callbacks. Windows encrypts stored tokens without a plaintext fallback. The local policy describes permissions, plaintext data, retention and remote revocation failures.
- Search checks archive containment, links and source identities. Source/provider instructions are inert text. Office/PDF extraction has bounds; those bounds are not a guarantee against every native parser vulnerability or allocation attack. Use a supported Windows environment and keep the application/runtime updated.
- PDF extraction/preview uses a separate Windows 10+ x64 process placed atomically in a Job Object before its first thread runs. Limits are 384 MiB process commit, 512 MiB aggregate job commit and eight processes per job; at most two parser jobs run concurrently. Timeouts, cancellation and guardian death terminate the tree. The verified supervisor hash is sealed inside ASAR, and unsupported/missing containment refuses parsing. Requests/results use a nonce-authenticated local named pipe with bounded data; extracted-content temporary files are not created. These controls constrain charged allocations, not total RSS/shared mappings, every OS allocation or filesystem/network access by compromised code. Original documents remain unchanged; limit failures are unavailable/partial content, never successful blank previews.
- Managed collection uses reviewed scope, bounded downloads, immutable complete-file publication and recovery receipts. Clear local data reviews scope and preserves originals and changed/unverified files; it is ordinary file deletion, not guaranteed forensic erasure. Concurrent hostile same-user filesystem races, malware and external backups are outside this guarantee.

## Windows distribution and updates

Build from the reviewed source for your own use. No prebuilt Windows download is published with this source snapshot. New local security-validation builds must use a fresh output directory. Packaging explicitly checks Electron fuses, executable-embedded ASAR integrity and source/package hashes. Fuses disable RunAsNode, NODE_OPTIONS and main CLI inspection; ASAR-only loading and embedded integrity are enabled. Existing file-protocol privileges remain for compatibility with this local-file UI and require separate review if the UI/protocol architecture changes. Native unpacked libraries and other non-ASAR resources still need trustworthy distribution/signature validation.

Locally built executables are unsigned unless you arrange signing. An unsigned executable and an adjacent SHA-256 file do **not** authenticate a publisher. ASAR integrity does not stop an attacker who can replace the entire unsigned executable and resources. Signing is optional for this personal project and is separate from sharing its source. Identify any shared build as unsigned, publish its checksum and limitations, and do not treat bypassing Windows warnings as a security check.

The existing signing helper accepts an explicitly selected installed, trusted code-signing certificate with its private key. It copies a candidate into a new output, signs/timestamps binaries and verifies the result; it does not buy a certificate, use a guessed identity or publish. Complete fuse/resource changes **before** signing. Recheck integrity, signatures, runtime tests and the exact final ZIP after signing. A future SignPath or Microsoft Store route requires its own owner account/eligibility/agreements and reviewed setup; neither is configured or approved by these source repairs. No automatic updater is implemented. Review the source and validate the exact artifact you build or obtain; a repository checksum alone does not establish publisher identity.

The post-package signer preserves the parser supervisor unchanged because its digest is already sealed inside ASAR. Its intended integrity chain is signed main executable → embedded ASAR integrity → exact helper digest; the helper is not independently publisher-signed. Environments requiring each helper to carry its own signature need a helper-before-ASAR signing pipeline and exact-artifact verification. Without the approved main publisher signature, the local candidate remains unauthenticated.

## Release responsibilities

The repository owner, GeoCeff, maintains this experimental source project. Before each candidate, review current upstream Electron/PDF.js/native-code advisories, run the pinned build and regression checks, and validate a new exact artifact. There is no background updater or promised security-support period.

For a suspected credential leak, stop the affected connection and revoke the real grant through its provider before reconnecting. A local disconnect cannot prove remote revocation while offline. Keep raw credentials out of reports; if Git contained a real secret, rotate/revoke it before coordinating history cleanup. Deleting a later copy alone is insufficient.

For a malicious-document or out-of-scope deletion report, stop the affected operation, retain minimal version/hash/steps evidence and preserve originals/backups. Reproduce with synthetic material in an isolated profile; do not keep running the suspect document to obtain a screenshot. Restore app-owned data only from a reviewed backup or rebuildable originals. Report the exact retained/deleted set without promising forensic recovery.

If a shared binary candidate is found unsafe, withdraw its download assets/draft, record its version/hash and tell actual recipients to stop using it through the channel used to share it. Validate a separately named replacement and provide the corrected hash and limitations. No automatic notification, account change or remote data deletion is performed by the app. Actual breach obligations and school notification decisions depend on the deployment and require the responsible owner/school review.

Sharing MIT source does not supply a verified Google application or school permission. Before offering a configured Google-connected build to other users, review the actual OAuth project and audience: provide accessible policy URLs and matching consent-screen details, complete any applicable Google verification, obtain required Workspace/school allowance, and validate revocation, offline failures and a permitted exact-package pilot. External / Testing projects retain their test-user and token-lifetime restrictions; no production Google consent setup is verified by this source publication. Registration, zero reported dependency advisories, unit tests and checksums are evidence about specific checks, not Google/school approval or a security certification.

Screen-reader speech, a clean second Windows device, broader platform support, parser fuzzing, hostile same-user races and a real approved course pilot remain separate checks. Absolute safety cannot be guaranteed. Known limitations and release evidence belong in RELEASE_CHECKLIST.md; never include private school materials or credentials in releases/issues.
